# 政府采购招标监控 · 全国版

一个能真跑起来的自动化流水线：从中国政府采购网采集**中央 + 地方**公开招标公告，
结构化出**项目名 / 采购单位 / 省份 / 预算 / 截止日期 / 品目 / 原文链接**，
去重、检测变化、生成按省份分组的日报、按关键词+省份订阅匹配，再推送到邮件 / Telegram / 企业微信。

零成本可跑，不需要任何付费服务，不登录、不绕验证码、不碰个人信息。

## 覆盖范围

| 数据源 | 路径 | 覆盖 |
|---|---|---|
| 中央公告 | `/cggg/zygg/` | 中央国家机关、部委、直属单位 |
| 地方公告 | `/cggg/dfgg/` | **全国 31 省**（省市县各级采购公告） |

关键发现：地方公告与中央公告的详情页结构**完全一致**，所以不需要为每个省写适配器，
一套解析器即可覆盖全国。这也是这个方案能低成本跑通的原因。

## 现在就能验证

```bash
cd tender-watch
python collect.py 2        # 采集 2 页/源（中央+地方，约 140 条）
python report.py           # 生成按省份分组的日报
python push.py --dry-run   # 订阅匹配预览
python run.py              # 一条命令跑完全流程
```

实测（2026-10-23）：采集 134 条，招标公告 29 条，
**预算命中 93%，截止日命中 100%，覆盖 28 个省份，详情页 0 错误。**

产出：
- `out/report_YYYYMMDD.html` — 带省份分布图的日报页面
- `out/report_YYYYMMDD.md` — 按省份分组的纯文本版
- `out/digest_*.txt` — 订阅推送摘要
- `data/health.json` — 自检结果（字段命中率、省份覆盖、告警）

## 文件说明

| 文件 | 作用 |
|---|---|
| `collect.py` | 多源采集 + 解析 + 分类 + 省份识别 |
| `report.py` | 去重指纹、变化检测、省份分组日报、健康自检 |
| `push.py` | 关键词 + 省份订阅匹配 + 多渠道推送 |
| `run.py` | 编排入口，失败重试，退出码驱动告警 |
| `config.json` | 订阅规则与推送渠道配置 |

## 配置订阅

复制 `config.example.json` 为 `config.json`。每条订阅支持：

```json
{
  "name": "订阅名",
  "keywords": ["软件", "信息系统"],     // 标题/品目/正文关键词，空数组=不限
  "provinces": ["江苏", "浙江", "上海"], // 省份白名单，空数组=全国
  "min_budget": 500000,                 // 最低预算（元）
  "max_budget": 0,                      // 最高预算（元），0/不填=不限
  "max_days_left": 30                   // 只看还剩几天截止的
}
```

推送渠道配置（密钥建议走环境变量 `TG_BOT_TOKEN` / `WECOM_WEBHOOK` / `SMTP_PASS`）：

```json
{
  "telegram_bot_token": "", "telegram_chat_id": "",
  "wecom_webhook": "",
  "smtp_host": "", "smtp_port": 465, "smtp_user": "", "smtp_pass": "",
  "mail_to": ["customer@example.com"]
}
```

## 省份识别策略

按可靠性从高到低，避免误判：

1. 概要表「行政区域」字段是有效省名 → 直接用
2. 「行政区域」是市/区县 → 查内置映射表（覆盖 200+ 常见市县）
3. 从标题里找 → 中央公告常把项目所在地写进标题
4. 地方公告再从正文兜底
5. 中央公告**不做正文兜底**，因为正文地名不代表项目所在地

踩过的坑：正文里的「**北京**时间」会让所有公告都变成北京。已做专门处理。

## 公告类型分类

- **招标公告** — 真正的商机（公开招标、竞争性磋商、谈判、询价、比选）
- **结果公告** — 中标/成交，用于分析竞争对手和价格
- **更正废标** — 变更通知
- **新闻** — 政策解读、会议报道，**已过滤**，不算商机

## 自愈设计

`report.py` 每次运行算健康指标，异常写入 `health.json` 的 `alerts`：

- 列表页返回空 → 源站可能改版或被封
- 招标公告为 0 条 → 解析规则失效
- 预算 / 截止日命中率跌破 60% → 页面结构变了
- 详情页失败率超 30% → 需要检查

配合 `run.py` 的非 0 退出码，可直接挂 GitHub Actions，坏了会自己报出来。

## 已验证的边界

- **只覆盖中国政府采购网**。它汇集了全国各省通过政府采购渠道发布的公告，
  但不等于各省公共资源交易中心的全量数据。工程建设招投标（发改委体系）
  主要在各省公共资源交易平台，那是另一套系统，尚未接入。
- 地方公告的「行政区域」字段有时是「市辖区」，此时靠标题/正文推断，可能识别不出。
  实测省份识别率约 90%。
- 预算字段对「详见公告正文」这类表述会返回空，已做正文二次查找，但仍可能漏。
- 源站偶发超时，已加 3 次重试 + 递增退避；抓取限速 0.6s/请求。

## 合规边界

只抓公开、无需登录的页面；不做验证码绕过、不伪造身份、不采集个人信息；
所有条目保留原文链接可溯源。
